# Глава 1. GPIO

## Что такое GPIO

**GPIO** (General-Purpose Input/Output) — это физический «пин» (ножка) чипа, которым управляет процессор. У каждого пина есть:

- **pad** — собственно металлическая ножка на корпусе чипа
- **MUX** (мультиплексор) — переключатель: к пину подключена либо функция периферии (SPI, UART, I2C…), либо общий GPIO
- **буфер выхода** — транзисторы, которые тянут пин к VCC (логическая 1) или GND (логический 0)
- **pull-up/pull-down** — слабые внутренние резисторы, чтобы пин не «висел» в неопределённом состоянии, когда никто им не управляет

```
            ┌──────────────────────────────────────┐
            │              F133 chip                │
   PAD ─────┤  ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐   │
   (ножка)  │  │ MUX │──│ drv │──│pull │──│ ... │   │
            │  └─────┘  └─────┘  └─────┘  └─────┘   │
            └──────────────────────────────────────┘
                 ↑        ↑        ↑
              функция   сила    подтяжка
```

На F133 6 портов (PB, PC, PD, PE, PF, PG), всего 72 пина. Каждый пин настраивается отдельно.

## Регистры порта

Каждый порт управляется набором регистров, отображённых в память (memory-mapped). Из user manual F133, раздел 9.7:

| Регистр   | Смещение от PIO_BASE | Что делает                          |
|-----------|----------------------|-------------------------------------|
| `Pn_CFG0` | `+0x0060` (для PC)   | Конфигурация пинов Pn0..Pn7 (4 бита на пин) |
| `Pn_CFG1` | `+0x0064` (для PC)   | Конфигурация пинов Pn8..Pn15        |
| `Pn_DAT`  | `+0x0070` (для PC)   | Уровни пинов (чтение/запись)        |
| `Pn_DRV0` | `+0x0074` (для PC)   | Сила драйвера (ток выхода)          |
| `Pn_PULL0`| `+0x0084` (для PC)   | Pull-up/down                        |

База PIO на F133 — `0x0200_0000`. Адреса для Port C:

```
PC_CFG0  = 0x0200_0060
PC_DAT   = 0x0200_0070
PC_DRV0  = 0x0200_0074
PC_PULL0 = 0x0200_0084
```

## Битовая раскладка PC_CFG0

В `PC_CFG0` пин `n` занимает 4 бита, начиная с бита `4*n`:

```
PC_CFG0:  [31:28]=PC7  [27:24]=PC6  [23:20]=PC5  [19:16]=PC4
          [15:12]=PC3  [11:8]=PC2   [7:4]=PC1    [3:0]=PC0
```

Для PC2 — это биты `[11:8]`. Значения (из таблицы 9.7.5.7 user manual):

| 4 бита  | Функция              | Примечание                  |
|---------|----------------------|-----------------------------|
| `0000`  | Input                | Чтение уровня с ножки       |
| `0001`  | **Output**           | Управление выходом          |
| `0010`  | SPI0 (CLK/CS/MOSI/MISO) | Для PC2..PC5 — функция SPI0 |
| `0011`  | SDC2                 | SD-карта                   |
| `0100`  | UART3 / BOOT-SEL     | Зависит от пина             |
| `0101`  | TWI3                 | I2C                         |
| `1110`  | PC-EINT              | Внешнее прерывание          |
| `1111`  | IO Disable           | Пин в Z-состоянии (Hi-Z)    |

## Как переключить пин в output и поднять/опустить

Код из `src/gpio.rs` — метод на `struct Pin`:

```rust
pub fn set_func(&self, f: Func) {
    let shift = self.pin * 4;
    let mask = 0xF << shift;
    unsafe {
        let old = read_volatile(self.cfg0_addr());
        write_volatile(self.cfg0_addr(), (old & !mask) | ((f as u32) << shift));
    }
}
```

Разбор по шагам для `PC2.set_func(Func::Output)`:

1. `pin = 2`, `shift = 2 * 4 = 8` — PC2 живёт в битах `[11:8]`
2. `mask = 0xF << 8 = 0x0000_0F00` — выделяем 4 бита PC2
3. `old & !mask` — **очищаем** биты PC2, не трогая остальные пины
4. `| (Output << 8)` — вписываем `0001` в биты `[11:8]`

Итог: в `PC_CFG0` биты `[11:8]` становятся `0001` — PC2 теперь output.

Для `PC2.set_high()`: пишем `1 << 2 = 0b0100` в `PC_DAT`. Контроллер выводит 3.3V на ножку PC2.
Для `PC2.set_low()`: пишем `0` в бит 2 — на ножке 0V.

## Почему `read_volatile` / `write_volatile`

Это memory-mapped регистры — каждая запись в адрес должна физически дойти до периферии. Обычная запись в Rust:

- может быть переупорядочена компилятором (оптимизация)
- может быть закэширована в регистре CPU и не дойти до памяти
- может быть объединена с соседними записями

`volatile` заставляет компилятор каждый раз **реально** выполнять чтение/запись по указанному адресу, в точности так, как написано. Без `volatile` пин может не переключиться.

## Типобезопасный API: `Pin` + `Port` + `Func`

Чтобы не передавать «магические числа» (какой порт, какой пин, какая функция), мы используем:

- `enum Port { B, C, D, E, F, G }` — порт
- `struct Pin { port: Port, pin: u32 }` — конкретная ножка
- `enum Func { Input, Output, Spi0, Spi1, Uart0, IoDisable, ... }` — функция (значение = регистровое)

```rust
#[derive(Clone, Copy)]
pub enum Port { B, C, D, E, F, G }

#[repr(u32)]
pub enum Func {
    Input     = 0b0000,
    Output    = 0b0001,
    Spi0      = 0b0010,  // для PC
    Spi1      = 0b0100,  // для PD
    Uart0     = 0b0110,  // для PE
    IoDisable = 0b1111,
}

#[derive(Clone, Copy)]
pub struct Pin { port: Port, pin: u32 }

impl Pin {
    pub const fn new(port: Port, pin: u32) -> Self { Self { port, pin } }
    pub fn set_func(&self, f: Func);
    pub fn set_high(&self);
    pub fn set_low(&self);
    pub fn set_pull(&self, p: Pull);
}

// Именованные константы — удобно и видно в IDE:
pub const PC2: Pin = Pin::new(Port::C, 2);
pub const PD11: Pin = Pin::new(Port::D, 11);
```

`#[repr(u32)]` у `Func` делает enum представленным в памяти как `u32` со значением варианта — можно сразу сдвигать и писать в регистр.

Вызов:

```rust
gpio::PC2.set_func(gpio::Func::Output);
gpio::PC2.set_high();
gpio::PC2.set_low();
```

Преимущества:
- IDE подсказывает варианты `Func::` и имена пинов `PC2`, `PD11`, ...
- Нельзя перепутать пин и функцию (разные типы)
- Один `Pin` работает для всех портов — не нужно плодить `pc_*`, `pd_*`, `pe_*` функции
- Добавить новый пин = добавить `pub const PX: Pin = Pin::new(Port::X, n);`

### Подводный камень `Func`

Значения в enum — регистровые, и они **привязаны к порту**: `Spi0=0b0010` корректен только для PC, а `Spi1=0b0100` — только для PD. Если вызвать `PD11.set_func(Func::Spi0)`, код скомпилируется, но запишет в PD11 функцию `0b0010`, которая на PD означает `LCD0-D15`, а не SPI. Имена подсказывают правильный выбор, но финальный контроль — за разработчиком (см. таблицу 9.7 в user manual).

## Практика: мигаем PC2

В `main.rs`:

```rust
gpio::PC2.set_func(gpio::Func::Output);

loop {
    gpio::PC2.set_high();
    utils::delay(1_000_000);
    gpio::PC2.set_low();
    utils::delay(1_000_000);
}
```

На логическом анализаторе, подключённом к PC2, видим:

```
  3.3V ─┐     ┌─────┐     ┌─────┐     ┌────
        │     │     │     │     │     │
   0V   └─────┘     └─────┘     └─────┘
              ↑ delay 1M циклов
```

Частота очень низкая (единицы герц), потому что `delay(1_000_000)` — это цикл из миллиона итераций `spin_loop`. Это нормально для первого урока.

## Самопроверка

- **Что будет, если писать `0x0000_0100` напрямую в `PC_CFG0` без `read_volatile`?**
  Затрём конфигурацию PC0, PC1, PC3..PC7 — они могут быть в SPI/UART режиме для других целей. Поэтому всегда читаем старое значение и модифицируем только нужные биты.

- **Почему `mask = 0xF << shift`, а не `0x1`?**
  Потому что на пин отведено 4 бита, а не 1. `0xF` = `0b1111` — все 4 бита.

- **Что произойдёт, если PC2 оставить в `INPUT` и писать в `PC_DAT`?**
  Ничего не изменится на ножке. У input нет выходного буфера — бит в `DAT` только читает текущий уровень с ножки.

- **Зачем `pull-up`/`pull-down`?**
  Чтобы пин не «висел» в неопределённом состоянии (когда никто не управляет — на входе). Pull-up держит незадействованный вход в логической 1, pull-down — в 0. У output подтяжка не нужна.

- **Что такое `IO Disable` (`1111`)?**
  Пин переходит в высокоимпедансное (Z) состояние — буфер отключён, пин не управляется ни процессором, ни периферией. Полезно для экономии энергии.
