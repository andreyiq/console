# Глава 2. CCU — тактирование и сброс периферии

## Зачем нужны тактовые сигналы

Любая цифровая схема внутри SoC — это куча триггеров (flip-flops). Триггер меняет состояние только по фронту тактового импульса (clock edge). Без такта периферия просто не работает — её транзисторы не переключаются.

```
           ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐
   CLK ────┘ └─┘ └─┘ └─┘ └─┘ └─┘
           ↑   ↑   ↑   ↑   ↑
        триггеры меняют состояние по каждому фронту
```

Частота такта определяет, как быстро работает периферия. Для SPI0 — это скорость передачи. Для UART — baud rate. Для CPU — сколько инструкций в секунду.

## Зачем gating (включение/выключение такта)

В SoC десятки периферий: SPI, UART, I2C, USB, EMAC, DE (display engine), TCON, DMIC, I2S… Если все они получают такт всегда — чип будет греться и жрать батарею. Поэтому у каждой периферии есть **clock gating** — бит, который включает/выключает подачу такта.

```
                  ┌──────────────┐
   OSC / PLL ─────┤   gate (AND)  │──── CLK к периферии
                  │      ↑       │
                  │   gating bit │
                  └──────────────┘
                    1 = пропустить
                    0 = замаскировать (нет такта)
```

По умолчанию после сброса все gating bits = 0 — периферия выключена. Чтобы запустить — нужно явно выставить бит.

## Что такое reset

При подаче питания или сбросе чипа все триггеры периферии находятся в случайном состоянии. **Reset** удерживает периферию в известном состоянии (обычно все нули), пока не стабилизируются питание и такты.

```
   reset = 0 (assert):  периферия удерживается в начальном состоянии, игнорирует входы
   reset = 1 (de-assert): периферия отпущена, начинает работать
```

Типичная последовательность включения периферии:
1. Включить тактовый сигнал (gating = 1)
2. Удержать reset (assert) — на всякий случай
3. Подождать несколько тактов
4. Отпустить reset (de-assert)
5. Периферия готова

На F133 в большинстве случаев reset уже asserted по умолчанию, поэтому достаточно:
1. Включить такт
2. Отпустить reset

## CCU на F133

**CCU** (Clock Control Unit) на F133 — блок по адресу `0x0200_1000`, который управляет всеми тактами и сбросами в чипе. Раздел 3.3.6 user manual.

Для каждой периферии у CCU есть обычно два регистра:

| Регистр | Что делает |
|---|---|
| `XXX_CLK_REG` | Источник такта (PLL/HOSC), делители (M, N), бит gating |
| `XXX_BGR_REG` | Биты gating (разрешение шины) и reset для группы периферии |

## Регистры SPI0

Из user manual, раздел 3.3.6.61 и 3.3.6.63:

### `SPI0_CLK_REG` (offset `0x0940`, адрес `0x0200_1940`)

| Биты | Имя | Значение |
|---|---|---|
| 31 | `SPI0_CLK_GATING` | 0 = clock OFF, 1 = clock ON |
| 26:24 | `CLK_SRC_SEL` | 000 = HOSC (24 MHz), 001 = PLL_PERI(1X), 010 = PLL_PERI(2X), 011/100 = PLL_AUDIO1 |
| 23:10 | `FACTOR_N` | делитель N (обычно 0 = 1) |
| 9:8 | `FACTOR_N` | 00=1, 01=2, 10=4, 11=8 |
| 3:0 | `FACTOR_M` | M = FACTOR_M + 1 (0..15 → 1..16) |

Итоговая частота: `SCLK = Источник / (M * N)`. Для нашего случая достаточно HOSC (24 MHz) без делителей — пишем `0x8000_0000` (только bit 31).

### `SPI_BGR_REG` (offset `0x096C`, адрес `0x0200_196C`)

| Бит | Имя | Значение |
|---|---|---|
| 17 | `SPI1_RST` | 0 = assert, 1 = de-assert |
| 16 | `SPI0_RST` | 0 = assert, 1 = de-assert |
| 1 | `SPI1_GATING` | 0 = mask, 1 = pass |
| 0 | `SPI0_GATING` | 0 = mask, 1 = pass |

Для включения SPI0: `0x0001_0001` (bit 16 + bit 0). Не трогаем SPI1.

## Почему `|` (OR), а не `=` (перезапись)

В `SPI_BGR_REG` биты SPI0 и SPI1 живут рядом. Если записать `0x0001_0001` напрямую — затрём биты SPI1 (сбросим его reset и gating, если кто-то их включил). Поэтому:

```rust
let old = read_volatile(SPI0_BGR_REG);
write_volatile(SPI0_BGR_REG, old | SPI0_RST | SPI0_GATING);
```

Читаем старое значение, выставляем только нужные биты, остальное не трогаем. Это правило для **любого** регистра, где биты относятся к разным независимым подсистемам.

## Код

`src/ccu.rs` — высокоуровневый API через enum `Peripheral`:

```rust
pub enum Peripheral {
  Spi0, Spi1, Uart0, Uart1,
  // будущие: I2c0, Smhc0, ...
}

struct PeripheralInfo {
  clk_reg: Option<*mut u32>,  // None у UART
  bgr_reg: *mut u32,
  rst_bit: u32,
  gating_bit: u32,
}

impl Peripheral {
  const fn info(&self) -> PeripheralInfo {
    match self {
      Peripheral::Spi0 => PeripheralInfo {
        clk_reg: Some(SPI0_CLK_REG),
        bgr_reg: SPI_BGR_REG,
        rst_bit: 1 << 16,
        gating_bit: 1 << 0,
      },
      // ... остальные периферии аналогично
    }
  }

  pub fn enable(&self) {
    let info = self.info();
    unsafe {
      if let Some(clk_reg) = info.clk_reg {
        let v = read_volatile(clk_reg);
        write_volatile(clk_reg, v | CLK_GATING_BIT);  // bit 31
      }
      let v = read_volatile(info.bgr_reg);
      write_volatile(info.bgr_reg, v | info.rst_bit | info.gating_bit);
    }
  }

  pub fn read_clk(&self) -> Option<u32> { /* ... */ }
  pub fn read_bgr(&self) -> u32 { /* ... */ }
}
```

В `main.rs`:

```rust
let spi0 = ccu::Peripheral::Spi0;
let clk_before = spi0.read_clk().unwrap_or(0);
let bgr_before = spi0.read_bgr();
spi0.enable();
let clk_after = spi0.read_clk().unwrap_or(0);
let bgr_after = spi0.read_bgr();
// печатаем в UART, чтобы убедиться что биты выставились
```

Добавить новую периферию = добавить вариант в enum + один match arm в `info()`. Методы `enable`/`read_clk`/`read_bgr` не меняются.

## Проверка

После прошивки в UART должно прийти что-то вроде:

```
hello
SPI0_CLK before=0x00000000 after=0x80000000
SPI0_BGR before=0x00000000 after=0x00010001
```

- `0x80000000` — bit 31 взведён (clock ON)
- `0x00010001` — bit 16 (SPI0_RST de-assert) и bit 0 (SPI0_GATING pass)

Если `after` равно `before` — что-то не сработало (возможно, CCU не читается, или такт CCU… CCU сам всегда под тактом, это не должно случиться).

## Самопроверка

- **Зачем gating, если можно просто оставить такт всегда включённым?**
  Энергопотребление. Каждая переключаемая ячейка потребляет ток. Если периферия не используется, её такт выключают — чип холоднее и экономнее.

- **Что будет, если включить такт, но не снять reset?**
  Периферия под тактом, но удерживается в начальном состоянии. Регистры не будут принимать значения, передача не пойдёт. На F133 reset по умолчанию уже asserted, поэтому мы его явно снимаем.

- **Почему `SPI0_CLK_REG` пишем через OR, а не `0x80000000` напрямую?**
  OR сохраняет биты источника/делителя, если кто-то их уже настроил. Прямая запись затёрла бы их. На свежем чипе разницы нет (там 0), но OR — безопасная привычка.

- **Можно ли включить SPI0 без CCU, просто подав такт извне?**
  Нет. Такт для периферии генерируется внутри SoC из OSC/PLL, и проходит через CCU gating. Внешний пин такта у SPI0 нет.
