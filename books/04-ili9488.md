# Глава 4. ILI9488 — дисплей по SPI

## Что такое ILI9488

**ILI9488** — контроллер TFT-дисплея от Ilitek, матрица 320×480 RGB. Стоит на 3.5" модулях. Умеет несколько интерфейсов: параллельный (8/16/18 бит), SPI (3-wire и 4-wire) и RGB (DPI). Мы используем **4-wire SPI**.

## 4-wire SPI на ILI9488

Четыре линии:

- **CSX** — chip select (активный низкий)
- **SCL** — такт (SPI clock)
- **SDA / SDI** — данные от мастера к дисплею (MOSI)
- **DCX** — Data/Command: **0 = команда**, **1 = данные**

Плюс **RESX** (hardware reset) и питание/подсветка.

MISO (SDO) нужен только если читать из дисплея (мы не читаем).

### Протокол передачи

Каждый «сеанс» = опустить CS, отправить команду, потом данные, поднять CS:

```
CS  ─┐                              ┌────
       │                              │
       └──────────────────────────────┘
DCX ───┐ ┌──────────────────────────┐──
       │ │                          │
       └─│ команда (0xNN)           │ данные, данные, ...
         │                          │
SCL    ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐     ┌─┐┌─┐┌─┐...
       │ ││ ││ ││ ││ ││ ││ ││ │     │ ││ ││ │
       └─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘     └─┘└─┘└─┘
MOSI ──[ 0xNN            ]──[ 0xD1 0xD2 0xD3 ... ]──
       ↑ DCX=0 (команда)    ↑ DCX=1 (данные)
```

В коде: `cs_low()`, `dc_low()` + `spi.send_byte(cmd)`, `dc_high()` + `spi.send(data)`, `cs_high()`.

## IM[2:0] — выбор интерфейса

Аппаратные пины IM0/IM1/IM2 выбирают интерфейс. Из datasheet ILI9488:

| IM2 | IM1 | IM0 | Интерфейс |
|-----|-----|-----|-----------|
| 0 0 0 | DBI Type B 24/18-bit bus |
| 0 0 1 | DBI Type B 9-bit bus |
| 0 1 0 | DBI Type B 16-bit bus |
| 0 1 1 | DBI Type B 8-bit bus |
| 1 0 1 | DBI Type C Option 1 (**3-wire SPI**, без DCX) |
| 1 1 0 | MIPI DSI |
| 1 1 1 | DBI Type C Option 3 (**4-wire SPI**, с DCX) |

Нам нужна **4-wire SPI** → **IM0=IM1=IM2=1** (все три к 3.3V).

## Init-последовательность

Дисплей не стартует сам — его надо «прогнать» серией команд. Последовательность для BOE 3.5" IPS из `docs/display/ili9488/BOE3.5IPS-ILI9488.TXT`:

1. `0xF7` + `[A9 51 2C 82]` — Adjust Control 3
2. `0xC0` + `[0F 0F]` — Power Control 1 (VGH/VGL)
3. `0xC1` + `[47]` — Power Control 2
4. `0xC5` + `[00 4D 80]` — VCOM Control
5. `0xB1` + `[B0 11]` — Frame Rate Control
6. `0xB4` + `[02]` — Display Inversion Control
7. `0x36` + `[E8]` — **MADCTL** (ориентация, см. ниже)
8. `0x3A` + `[55]` — **Pixel Format = RGB565** (2 байта/пиксель)
9. `0x21` — Display Inversion ON (нужно для IPS-панели)
10. `0xE9` + `[00]` — Set Image Function
11. `0xF7` + `[A9 51 2C 82]` — Adjust Control 3 (повтор)
12. `0xE0` + `[15 байт]` — Positive Gamma
13. `0xE1` + `[15 байт]` — Negative Gamma
14. `0x11` — **Sleep Out** + подождать ~120 ms
15. `0x29` — **Display ON** + подождать ~20 ms

Перед всем этим — hardware reset (RST низко на 50 ms, высоко на 150 ms).

## MADCTL (0x36) — ориентация

Биты регистра `MADCTL`:

| Бит | Имя | Что делает |
|-----|-----|------------|
| 7 | MY  | Row Address Order (вертикальный флип) |
| 6 | MX  | Column Address Order (горизонтальный флип) |
| 5 | MV  | Row/Column Exchange (поворот 90°) |
| 4 | ML  | Vertical Scroll Order |
| 3 | RGB | 0 = RGB, **1 = BGR** (важно для IPS!) |
| 2 | MH  | Horizontal Scroll Order |

У нас `MADCTL = 0xE8 = 0b1110_1000`:
- MY=1, MX=1, MV=1 → повёрнутая ориентация (landscape 480×320)
- RGB=1 → **BGR order** (IPS-панели обычно требуют BGR, не RGB)

Если картинка перевёрнута/зеркальная — меняешь биты MY/MX/MV. Если цвета инвертированы (красный ↔ голубой) — меняешь бит RGB.

## RGB565 — формат пикселя

`0x3A = 0x55` = 16-bit per pixel, формат **RGB565**:

```
старший байт:  R R R R R G G G    (R5 G3)
младший байт:  G G G B B B B B    (G3 B5)

[RRRRR][GGG GG][BBBBB]
  5     6      5    = 16 бит
```

Примеры цветов:

| Цвет | RGB565 (hex) |
|------|--------------|
| чёрный   | `0x0000` |
| белый    | `0xFFFF` |
| красный  | `0xF800` |
| зелёный  | `0x07E0` |
| синий    | `0x001F` |
| жёлтый   | `0xFFE0` |
| голубой  | `0x07FF` |
| пурпурный| `0xF81F` |

В SPI байты идут **старший первым** (MSB first): для красного `0xF800` отправляем `[0xF8, 0x00]`.

## Рисование: окно + Memory Write

Дисплей сам хранит «курсор» — куда писать следующий пиксель. Чтобы нарисовать прямоугольник, задаём окно и шлём пиксели подряд:

1. `0x2A` (Column Address Set) + `[x_start_hi, x_start_lo, x_end_hi, x_end_lo]`
2. `0x2B` (Page Address Set) + `[y_start_hi, y_start_lo, y_end_hi, y_end_lo]`
3. `0x2C` (Memory Write) — дальше идут пиксели, по 2 байта на точку

После `0x2C` контроллер ждёт пиксели и автоматически инкрементирует курсор (в пределах окна). Когда доходит до конца строки — переходит на следующую. Когда доходит до конца окна — останавливается (или зацикливается, зависит от настроек).

Для заливки всего экрана: окно `(0,0)→(480,320)`, потом шлём `480*320 = 153600` пикселей = `307200` байт.

## Проблема скорости

153600 пикселей по SPI — это много. На медленном делителе `0x1000` (как сейчас) заливка будет занимать секунды. Это нормально для первого урока. Потом:

- Ускорчим SPI (делитель `0x0000` → ~12 MHz)
- Будем слать буфером через `spi.send(buf)`, а не побайтово
- В идеале — через DMA (Этап 6)

## Структура драйвера

`src/display.rs`:

```rust
pub struct Display {
  spi: Spi,    // обёртка над SPI0
  dc: Pin,     // PE0 — Data/Command
  rst: Pin,    // PE1 — Reset
}

impl Display {
  pub fn new(spi: Spi, dc: Pin, rst: Pin) -> Self;
  pub fn init(&self);              // RST toggle + init-последовательность
  pub fn fill(&self, color: u16); // залить экран цветом RGB565
}
```

Использование в `main.rs`:

```rust
let display = display::Display::new(
  spi::Spi::Spi0,
  gpio::PE0,  // DCX
  gpio::PE1,  // RESX
);
display.init();
display.fill(0xF800); // красный
```

## Самопроверка

- **Зачем DCX, если есть CSX?** CSX выбирает чип (как в любой SPI-flash). DCX distinguishes command byte от data bytes — это специфика дисплеев, в обычной SPI-памяти такого нет.

- **Что будет если не сделать hardware reset?** Дисплей может быть в случайном состоянии после подачи питания. Reset гарантированно приводит его в известное состояние. Можно пропустить, но тогда init может не сработать с первого раза.

- **Почему RGB565, а не RGB888?** 2 байта/пиксель вместо 3 — экономия SPI-пропускной способности и памяти. Для NES-эмулятора (6-битный цвет) RGB565 хватает с запасом.

- **Почему `0x21` (Inversion ON) нужен для IPS?** IPS-панели физически инвертированы по сравнению с TN. Команда `0x21` компенсирует это программно. Без неё цвета будут «неправильные» (тёмное вместо светлого).

- **Можно ли рисовать не весь экран, а прямоугольник?** Да — задаёшь окно `0x2A/0x2B` на нужный прямоугольник и шлёшь ровно `w*h` пикселей. Курсор сам сдвигается внутри окна.
