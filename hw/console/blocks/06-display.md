# Блок 6 — ДИСПЛЕЙ

Панель 3.5″ ILI9488 480×320 на шлейфе FFC-40 0.5 мм, разведённая **сразу под
два интерфейса**: i8080 16 бит и 4-проводный SPI, переключение одним сигналом
`IM_SEL`. Плюс подсветка через MOSFET на `PD22`.

Блок закрывает строки ТЗ **«Экран»** и **«Подсветка»** и требование 4
(«Экран разведён сразу под оба интерфейса … Софт стартует на SPI, потом
переезжает на 8080 без перепайки»). По BOARD-draft.md §9 это шаг 3.

первоисточник, как даташит любой микросхемы из `docs/chips/`, просто лежит
отдельно:

| Даташит разъёма | `docs/chips/FFC-40p-0.5mm_Hirose_C202114.pdf` — Hirose FH12 |

## 1. Микросхемы

Своей микросхемы нет: контроллер ILI9488 сидит на стекле панели. По CHIPS.md
блок закрывает **§4 «Подсветка экрана — без драйвера, как на стенде»**.

Покупается: разъём FFC-40 (`C202114`, Hirose FH12, $0.70) и N-канальный MOSFET
(деталь не выбрана, требования — §7.1).

Выводы F133, которые закрывает блок: **весь банк PD целиком**, выводы 52…76 —
23 штуки, плюс `PC2` (19) и `PC4` (17) вторым концом на общей шине SPI0.

### 2.4 Страпы `IM` (спека Table 3 «Interface Selection», стр. 11)

| `IM2` | `IM1` | `IM0` | Интерфейс |
|---|---|---|---|
| 0 | 0 | 0 | DBI Type B 24-bit (`DB_EN` = 1) |
| 0 | 0 | 0 | DBI Type B 18-bit (`DB_EN` = 0) |
| 0 | 0 | 1 | DBI Type B 9-bit |
| **0** | **1** | **0** | **DBI Type B 16-bit** ← наш i8080 |
| 0 | 1 | 1 | DBI Type B 8-bit |
| 1 | 0 | 1 | DBI Type C Option 1 (3-line SPI) |
| 1 | 1 | 0 | DSI |
| **1** | **1** | **1** | **DBI Type C Option 3 (4-line SPI)** ← наш SPI |

Два следствия, на которых держится весь блок:

- **`IM1` = 1 в обоих режимах** → жёстко на `IOVCC`, ни резистора, ни GPIO;
- **`IM0` = `IM2` в обоих режимах** (0/0 и 1/1) → это **одна цепь** `IM_SEL`,
  один GPIO на оба вывода шлейфа.

Цена второго интерфейса по страпам — **ровно один вывод F133**.

### 2.5 Схема применения от поставщика панели

Тот же поставщик, отдельный лист `3.5-40pin应用电路Protel Schematic.pdf`.
Это не пересказ, а чертёж — на нём три варианта подключения и общие замечания.

Примечания в шапке:

1. интерфейс выбирается страпами `IM0/1/2`;
2. `VCC`/`IOVCC` панели — **3.3 В**;
3. **«背光供电：正极A_3.3V, 75mA，负极K1-6可接地，或者接一起联接到一个三极管
   与主控芯片IO软件控制»** — питание подсветки: анод `A` на **3.3 В, 75 мА**,
   катоды `K1-6` можно посадить на землю либо соединить вместе и завести на
   транзистор под управлением GPIO;
4. выводы тачскрина при неиспользовании висят в воздухе.

Панель «使用MCU16位接口» (16-битный MCU-интерфейс) — ровно наш режим:

- `8PIN_FMARK` — в воздухе;
- **`13PIN_SDA` — на GND**;
- `14PIN_SDO` — в воздухе;
- `39PIN_IM1` — на `VCC`;
- `38/40PIN_IM0/2` — на GND.

Панель «使用串口4线SPI接口» (4-проводный SPI):

- **`12PIN_RD` — на `VCC`**;
- `38/39/40PIN_IM0/1/2` — на `VCC`;
- **`17-32PIN_DB0-15` — на GND**;
- и прямо там же красным: **«3.5寸TFT不建议用串口驱动»** — для 3.5″ панели
  последовательный интерфейс **не рекомендуется**.

Схемотехника на листе:

| | |
|---|---|
| `C6` 1.0 мкФ/10 В | на `VCC`/`IOVCC` |
| `R7` **0 Ω** | последовательно с анодом подсветки от 3.3 В |
| `R1`…`R6` | по **два посадочных места на каждый вывод `IM`** — одно на 3.3 В, одно на GND; ставится нужное |
| `Q1` S8050 + `R1` 10k в базу + `R2` 10k на 3.3 В | рекомендуемый ключ подсветки; `BL_CTR` **подтянут вверх**, то есть подсветка по умолчанию включена |

### 2.7 Интерфейс i8080 в F133 (user manual §5.1.3.5, Table 5-7, стр. 372)

| Сигнал | Описание | Тип |
|---|---|---|
| `CS` | Chip select, active low | O |
| `WR` | Write strobe, active low | O |
| `RD` | Read strobe, active low | O |
| `A1` | Address bit, управляется `LCD_CPUI/F` BIT26/25 | O |
| `D[23..0]` | Digital RGB output signal | I/O |

Там же текстом: «WR is 180° delay of DCLK; CS is active when pixel data is
valid; **RD is always set to 1**; A1 is set by `LCD_CPUI/F`». То есть в режиме
8080 все четыре управляющих сигнала формирует железо TCON, софт их не дёргает.
`A1` — это и есть `RS` панели (выбор команда/данные).

Общий список внешних сигналов — Table 5-1, стр. 367: `LCD0-D[23:0]`,
`LCD0-CLK`, `LCD0-VSYNC`, `LCD0-HSYNC`, `LCD0-DE`.

### 2.8 Раскладка i8080 по выводам `LCD0` (user manual §5.1.3.2, стр. 368–369)

**Это ключевая таблица блока.** Широкая таблица «Control Signal and Data Port
Mapping» показывает, во что превращается каждый вывод `LCD0` в каждом режиме
панели. Колонки читались не глазами, а по координатам слов

| `LCD0-CLK` | `DCLK` | **`WR`** |
| `LCD0-DE` | `DE` | **`RS`** |

### 2.9 Состояние выводов PD после сброса (user manual §9.7.5.11, стр. 1054)

`PD_CFG0` (0x0090), **default value `0xFFFF_FFFF`**. Значения полей `PDn_SELECT`:

```
0000: Input     0001: Output    0010: LCD0-Dn   ...   1110: PD-EINTn   1111: IO Disable
```

Значит **сразу после сброса каждый вывод банка PD находится в `IO Disable`**,
то есть в третьем состоянии. Из этого следуют три вещи:

- трюк «два вывода F133 на одну линию шлейфа» безопасен: неактивный вывод
  переводится в `1111` и физически отключён от цепи;
- цепи `RESET` и `IM_SEL` панели до старта софта **висят в воздухе** и требуют
  резисторов, задающих уровень;
- вход `CS` панели тоже висит, пока софт не возьмёт `PD21`.

## 3. MangoPi (`docs/mangopi/mq_sch_v1.6.pdf`)

У MangoPi панель **другая** — 24-битная RGB на своём 40-выводном шлейфе, а не
i8080. Поэтому она не образец для нашего разъёма, но три вещи проверяет.

### 3.1 Какие `LCD0-D` вообще выведены на корпус (стр. 1, разъём `P1`)

`P1` подписан по цветам: `R0`, `R1` — **не подключены**, `R2`…`R7` идут на
`LCD_D18`…`LCD_D23`; `G0`, `G1` не подключены, `G2`…`G7` — на
`LCD_D10`…`LCD_D15`; `B0`, `B1` не подключены, `B2`…`B7` — на
`LCD_D2`…`LCD_D7`.

То есть серийная плата на этом же чипе пользуется ровно набором
`D2`…`D7`, `D10`…`D15`, `D18`…`D23` — восемнадцатью линиями. Наш
шестнадцатибитный набор из §2.8 целиком внутри него. Прочие `LCD0-D`
(`D0`, `D1`, `D8`, `D9`, `D16`, `D17`) на F133 в eLQFP128 живут в банке PB
(Table 4-3: `PB2`…`PB7`), и MangoPi их для дисплея не берёт.

### 3.2 Последовательные резисторы (стр. 3)

Читано нетлистером `tools/mangopi_net.py`, потом проверено кропом.

**`R59` 33 Ω стоит ровно на одной цепи — `LCD_CLK`, вывод 75 (`PD18`).**
Соседние `LCD_DE` (76), `LCD_D23` (74), `LCD_D22` (73), `LCD_D21` (72),
`LCD_D20` (71), `LCD_D18` (70), `LCD_D19` (69), `LCD_D15` (68), `LCD_D14` (67)
уходят с выводов напрямую, без единого резистора.

Тот же кроп подтверждает перестановку из §2.6: **70 = `PD12` → `LCD_D18`,
69 = `PD13` → `LCD_D19`**.

### 3.3 Подсветка (стр. 1)

`U5 MT9284-28J` — повышающий драйвер светодиодов: `LCD_PWM` → `EN` (с
подтяжкой `R36` 5.1k на `VCC3V3`), выход `LEDA` на разъём, `LEDK` → `FB` и
`R4` 2R7 на землю. Подписью на схеме — **38 мА**.

Существенно здесь не топология (у них цепочка светодиодов с высоким `VF`), а
то, что **`EN` подтянут вверх**: подсветка по умолчанию включена, как и в §2.5.

Питание панели: `VDD` на `VCC3V3`, развязка `C59` 0.1 мкФ + `C60` 10 мкФ прямо
у разъёма. `DISP` и `NC/PSSEL` посажены на `VCC3V3`.

## 4. Xassette (`../../ref/Xassette-Asterisk/`)

Тоже **другая панель**: `J1` — `Conn_01x40` в футпринте
`TE_4-1734839-0_1x40-1MP_P0.5mm_Horizontal`, но распиновка RGB:
1 `LCD_K`, 2 `LCD_A`, 3 `GND`, 4 `+3V3`, 5…28 `LCD0-D0`…`LCD0-D23`,
29 `GND`, 30 `LCD0-CLK`, 31 не подключён, 32 `LCD0-HSYNC`, 33 `LCD0-VSYNC`,
34 `LCD0-DE`, 35 `NoConn`, 36 `GND`.

Обратите внимание: Xassette заводит на разъём **все 24** линии `LCD0-D`,
включая `D0`, `D1`, `D8`, `D9`, `D16`, `D17` — то есть задействует и банк PB.

Подсветка: `U6 SY7201ABC` — повышающий драйвер от `+5V`, `L5` 10 мкГн, `D2`,
`C45` 0.1 мкФ, `C46` 10 мкФ, `R19` **2R2** в цепи обратной связи, выходы
`LCD_A`/`LCD_K` на разъём. Ровно то, что CHIPS.md §4 разобрал и отклонил: у них
последовательная цепочка светодиодов, у нас три параллельных с `VF` 3.2 В.

## 5. Расхождения

**1. Три разных числа для тока подсветки.** Спека §5.2 нормирует равномерность
при `IF` = 90 мА; лист применения (§2.5) пишет «正极A_3.3V, **75mA**»; CHIPS.md
§4 взял 90 мА и поделил на три строки по 30. Вывод: **75 мА — рабочая точка,
90 мА — условие измерения равномерности**, это не одно и то же. Расчёт ведём по
75 мА, запас по разъёму и ключу считаем по 90.

**2. Два разных потолка `VF`.** Спека §6.0 (вывод 33): «3.0V-3.4V
Typical:3.2V». Спека §5.2: `VF` типовое 3.2, **максимум 3.5**. Числа
противоречат друг другу в пределах одного документа. Разбор — §7.6.

**3. Спека — на TN-версию, панель у нас IPS.** Имя файла и §1.0 говорят о TN,
а рядом в той же папке лежит `BOE3.5IPS-ILI9488.TXT` с инициализацией, где
`0x3A` = `0x55` (RGB565) и `0x21` (инверсия для IPS). Интерфейс, распиновка и
страпы у обеих версий одинаковы — это свойство ILI9488, а не стекла; отличаются
гамма, `VCOM` и, возможно, подсветка. Вывод: **на схему это не влияет**, на
инициализацию и на §7.6 — влияет.

**4. Рекомендованный поставщиком ключ подсветки не проходит по расчёту.**
`Q1` S8050 с `R1` 10k в базе: `IB` = (3.3 − 0.7)/10k = 0.26 мА, для 75 мА нужен
`hFE` ≥ 288, а у S8050 он нормируется от 85. При `hFE` = 100 через подсветку
пойдёт 26 мА вместо 75, то есть треть яркости. Ставим **MOSFET** — у него ток
затвора нулевой и вопроса не возникает. Схему поставщика повторяем в части
подтяжки, а не в части прибора.

**5. Обе референсные платы ставят повышающий драйвер, мы не ставим.** MangoPi
`MT9284-28J`, Xassette `SY7201ABC`. Но у обеих панель с последовательной
цепочкой светодиодов, где `VF` выше питания и без буста никак. У нашей панели
три параллельные строки по 3.2 В, и **поставщик той же панели прямо пишет
«正极A_3.3V»**. Расхождение мнимое: платы решают другую задачу.

**6. Ни один 40-выводной шлейф с референсов нам не подходит.** Разъём выглядит
одинаково (40 контактов, 0.5 мм), распиновка не совпадает ни с MangoPi, ни с
Xassette. Единственный источник распиновки — §2.3. Это стоит держать в голове
при разводке: скопировать чужой футпринт можно, чужие цепи — нет.

**7. Последовательные резисторы: MangoPi ставит один, спека не требует ни
одного.** Берём практику MangoPi — 33 Ω на самый быстрый сигнал (§6.4).

**8. BOARD-draft.md устарел в двух местах.** Он числит `PD0` и `PD9` в
свободных (§5 «Свободно») — после этого блока свободных выводов в банке PD не
остаётся вовсе. И он оценивает цену второго интерфейса в «2 пина», не считая
линию `SDA` (§6.3).

### 6.1 Общая раскладка шлейфа

Свободных выводов в банке не остаётся.

### 6.2 Питание панели

`VCC` (6) и `IOVCC` (7) — обе на `+3V3`. Развязка у разъёма: `C601` 0.1 мкФ +
`C602` 10 мкФ, как у MangoPi (§3.3). Лист применения обходится одним 1.0 мкФ
(§2.5) — берём вариант MangoPi, он щедрее и это живая плата.

Потребление блока по `+3V3`: 5 мА панель (§2.2) + 75 мА подсветка (§2.5) =
**80 мА**. Бюджет рельсы в 02-power.md §7 — 0.5 А худшего случая при 2 А от
`SY8089`; запас есть.

Предел `VDD` панели 3.6 В (§2.2), рельса даёт 3.32 В номинала (02-power.md §3,
делитель `R8`/`R9`) — запас 0.28 В.

### 6.3 Два интерфейса на одном шлейфе

Конфликтует **ровно один вывод шлейфа — 10**. В 8080 это `RS`, который обязан
идти с `LCD0-DE` (§2.7: `A1` формирует железо TCON). В SPI это `SCL`, который
обязан идти с аппаратного `SPI0-CLK`, иначе кадр не вытолкнуть.

Решение: **два вывода F133 на одну линию**, каждый через свой резистор,
неактивный переводится в `IO Disable` (§2.9).

| Ветка | Вывод F133 | Резистор |
|---|---|---|
| 8080 | `PD19` (76) `LCD0-DE` | `R604` 33 Ω |
| SPI | `PC2` (19) `SPI0-CLK` | `R605` 33 Ω |

Остальные линии второго режима **нового вывода F133 не стоят**:

- вывод 11: в 8080 это `WR` с `LCD0-CLK`, в SPI — `D/CX`, обычный уровень;
  один и тот же `PD18`, только другой мукс;
- вывод 9 `CS`: в 8080 его дёргает TCON с `LCD0-VSYNC`, в SPI — тот же `PD21`
  как GPIO;
- вывод 13 `SDA`: в 8080 не используется, в SPI — `PC4` (`SPI0-MOSI`), уже
  занятый флешкой.

**Плата за это:** `PC2` и `PC4` — шина SPI0, на ней же сидит `W25Q32`. Пока
линия 10 шлейфа висит на `PC2`, **в режиме 8080 шиной SPI0 пользоваться
нельзя**: любой такт флешки поедет в `RS` панели. Это терпимо (прошивку
вычитывает BROM до инициализации дисплея, сейвы идут на microSD), а если
понадобится — **`R605` и есть точка размыкания**: снял резистор, SPI0 свободен,
SPI-режим дисплея потерян. Ничего больше выпаивать не нужно.

### 6.4 Последовательные резисторы

`R603` 33 Ω на вывод 11 (`WR`) — по образцу `R59` MangoPi (§3.2), которая стоит
на том же выводе F133 `PD18` и ни на каком другом. `WR` — самый быстрый сигнал
шины: он строб, по нему защёлкивается каждое слово.

`R604`, `R605` 33 Ω — см. §6.3.

На `DB0`…`DB15` резисторов **нет**: MangoPi на данных не ставит ни одного, а
шестнадцать лишних деталей на плате, которая травится дома, — это шестнадцать
шансов на непропай. Риск записан в §7.7.

### 6.5 Резисторы, задающие уровень

Все четыре нужны потому, что после сброса выводы PD в третьем состоянии
(§2.9), а панель должна вести себя предсказуемо ещё до первой строчки нашего
кода.

| | Куда | Зачем |
|---|---|---|
| `R606` 10k вверх | вывод 12 `RD` | спека прямо требует «Fix to IOVCC level when not in use» (§2.3), и лист применения ставит `RD` на `VCC` в SPI-режиме (§2.5) |
| `R607` 10k вверх | вывод 9 `CS` | пока BROM читает флешку по SPI0, такт идёт и в линию 10 шлейфа (§6.3); панель обязана быть невыбранной |
| `R608` 10k **вниз** | вывод 15 `RESET` | держит панель в сбросе от подачи питания до момента, когда софт возьмёт `PD9`. Без него панель выходит из сброса в неизвестный момент и с неизвестными страпами |
| `R609` 10k вверх | выводы 38/40 `IM_SEL` | задаёт режим **до** снятия сброса. Вверх = `IM0`=`IM2`=1 = 4-line SPI — режим, в котором работает текущий код (ТЗ, требование 4) |

Порядок для софта отсюда получается жёсткий: **сначала выставить `IM_SEL`,
потом отпустить `RESET`.** Панель читает страпы при выходе из сброса.

`IM1` (39) — на `+3V3` напрямую: он равен 1 в обоих наших режимах (§2.4), и
посадочное место резистора тут ничего не даёт.

### 6.6 Подсветка

```
+3V3 ──[R601 0 Ω]──► FFC 33 (LED-A)

                                    FFC 34,35,36 (LED-K1..K3)
                                              │
PD22 (52, PWM7) ──┬──► затвор Q601 (N-MOSFET) ┘
                  │          исток ──► GND
             [R602 10k]
                  │
                +3V3
```

- `R601` **0 Ω** — посадочное место балласта. Поставщик ставит ровно 0 Ω (`R7`,
  §2.5), стенд работает так же. Номинал можно подобрать потом, не трогая плату.
- `Q601` — N-канальный MOSFET, катоды на сток, исток на землю. Не биполярный —
  причина в §5 п. 4.
- `R602` 10k **вверх** — подсветка по умолчанию включена. Так делают **оба**
  источника: лист применения (`R2` 10k на `VCC3.3V`, §2.5) и MangoPi (`R36`
  5.1k на `VCC3V3`, §3.3). Плата за это записана в §7.8.

Ток 75 мА на три катода — по 25 мА на контакт разъёма при допустимых 0.5 А
(даташит FH12, Product Specifications). Анод несёт все 75 мА на одном контакте
— тоже с шестикратным запасом.

### 6.7 Имена цепей

Метки называются по функции **вывода панели**, а не по муксу F133: блок про
дисплей, и читать схему проще так. Соответствие мукса — таблица §2.8.

`LCD-DB0`…`LCD-DB15`, `LCD-CS`, `LCD-RS`, `LCD-WR`, `LCD-RD`, `LCD-RST`,
`LCD-IM`, `LCD-BL`, плюс общие с блоком 4 `SPI0-CLK` и `SPI0-MOSI`.

Метки у ног F133 ставит **блок 8** — правило из 07-clock-reset.md §6.4 и

дополнить 23 выводами банка PD со ссылкой на этот документ; `PC2` и `PC4`

## 7. Допущения и открытые вопросы

### 7.1 MOSFET подсветки не выбран

Требования посчитаны, деталь — нет. Нужно: N-канальный, **логический уровень**
(`VGS(th)` ≤ 1.5 В, полностью открыт при `VGS` = 2.5 В — затвор качается от
3.3 В), `ID` ≥ 0.5 А с запасом на 75 мА, `RDS(on)` ≤ 100 мОм, корпус SOT-23.
Падение на ключе прямо съедает запас на светодиодах (§7.6), поэтому
`RDS(on)` тут не формальность: 100 мОм × 75 мА = 7.5 мВ, приемлемо.

Пока деталь не выбрана и её даташит не лежит в `docs/chips/`, футпринта у `Q601`
не будет — как у дросселей `L1`…`L3` и движка `SW1`.

### 7.2 Вариант разъёма (верхний или нижний контакт) не определён

FH12 бывает top contact, bottom contact и вертикальный (даташит, §Features
п. 4). Какой нужен — зависит от того, какой стороной шлейф панели выходит и как
панель ляжет в корпус. Электрически всё равно, на футпринт влияет. Решается
вместе с механикой (ТЗ, «Осталось выбрать» п. 4).

### 7.3 `FMARK` (tearing effect) не подключён

Спека разрешает («If not used, open this pin»), лист применения делает именно
так. Но в эмуляторе с полнокадровым выводом разрыв кадра виден.

Подключить некуда: банк PD израсходован полностью (§6.1). Формально у F133 есть
`DBI-TE` на `PD13` (Function4, §2.6), но `PD13` занят под `DB11`. Остаётся
свободный банк PB — то есть провод через весь лист и через всю плату ради
сигнала, который нужен только если тиринг реально полезет.

**Решение отложено до первого изображения на экране.** Если тиринг будет
мешать — это доработка платы, а не переразводка.

### 7.4 Конкуренция на выводе 10 шлейфа

Если софт по ошибке включит одновременно `LCD0-DE` на `PD19` и `SPI0-CLK` на
`PC2`, встречный ток пойдёт через `R604` + `R605` = 66 Ω, то есть до 50 мА при
разнополярных уровнях. Это заметно больше 6 мА, на которые нормирован вывод
(02-power.md §2.2).

Защита — программная: `PD_CFG` после сброса и так `IO Disable` (§2.9), и
неактивную ветку нужно возвращать в `1111`, а не в `Input`. Аппаратно поднять
резисторы до 82 Ω можно, но тогда на `SCL` в SPI-режиме появится постоянная
времени 82 Ω × ~15 пФ. **Принято: 33 Ω и правило для софта.**

### 7.5 В режиме SPI шину `DB0`…`DB15` держит софт, а не резисторы

Спека требует «Fix to GND level when not in use» (§2.3), лист применения сажает
`17-32PIN_DB0-15` прямо на землю (§2.5). Шестнадцать резисторов вниз мы не
ставим — вместо этого софт переводит `PD1`…`PD17` в выход и выдаёт 0 **до**
снятия `RESET` панели.

Чем рискуем: между подачей питания и этим моментом входы `DB` панели висят в
воздухе (§2.9). Панель при этом в сбросе (`R608`), но её входные буферы под
питанием, и плавающий вход КМОП-буфера — это сквозной ток. Величина неизвестна,
время — доли секунды. **Считаю допустимым, но это допущение, а не факт.**

### 7.6 Запаса по напряжению на подсветке практически нет

Считаем от рельсы 3.32 В (02-power.md §3):

| Случай | `VF` | Остаток на `R601` + ключ |
|---|---|---|
| типовой (§2.2) | 3.2 В | 0.12 В |
| потолок по §6.0 спеки | 3.4 В | **−0.08 В** |
| потолок по §5.2 спеки | 3.5 В | **−0.18 В** |

При `VF` выше 3.3 В подсветка от рельсы 3.3 В **не зажжётся вовсе**. Против
этого есть ровно один аргумент, зато сильный: **поставщик той же самой панели
пишет «正极A_3.3V, 75mA»** (§2.5), то есть 3.3 В — это заявленная рабочая
точка, а «максимум 3.5» относится к разбросу партии и, видимо, к другому току.
Плюс стенд с этой панелью уже светится от 3.3 В (CHIPS.md §4).

Что принимаем осознанно: ток зависит от температуры (`VF` падает ~2 мВ/°C, за
игру панель греется на 20–40°) и уходит в ноль в конце разряда, когда рельса
3.3 В садится вслед за батареей. ШИМ-регулировка при этом работает — ключ рвёт
цепь, запас напряжения ему не нужен.

Страховка на плате: `R601` — посадочное место, а не перемычка. Если на живой
плате яркости не хватит, туда встанет буст, а не новая плата.

### 7.7 Шестнадцать линий шины без резисторов и без экрана

Данных резисторов нет (§6.4), шлейф FFC не экранирован, плата двухслойная и,
возможно, травленая дома. При 480×320×16 бит и 60 кадрах это ~150 Мбит/с
суммарно по шине. Основной риск блока по ЭМС.

Обосновано тем, что MangoPi так и делает на серийной плате (§3.2). Не проверено
ничем: у MangoPi шлейф RGB с непрерывным потоком, у нас 8080 со стробом, и
характер помех другой.

### 7.8 Подсветка включена по умолчанию

`R602` тянет затвор вверх (§6.6), как оба источника. Значит подсветка горит с
момента появления `+3V3` — до старта софта, во время загрузки и, что важнее,
если консоль зависла. Это 75 мА × 3.3 В = 250 мВт из батареи.

Взамен получаем индикатор: экран засветился — рельса 3.3 В жива. На этапе 5
первого запуска это единственное, что вообще видно.

Обратный вариант (подтяжка вниз) отвергнут только потому, что оба источника
выбрали вверх. Меняется одним резистором.

### 7.9 Способна ли TCON F133 прокачать эту панель — не проверено

User manual заявляет «Supports i8080 interface, up to 800 × 480@60fps»
(§5.1 «Overview», стр. 365). 480 × 320 внутри этого. Но:

- порядок инициализации 8080 (Figure 5-13 «i8080 Mode Initial Process»,
  стр. 384) содержит одиннадцать шагов и заканчивается «tri start», то есть
  режим не сводится к «настроил и забыл»;
- сходятся ли тайминги `WR` TCON с требованиями ILI9488, не проверялось: спека
  панели в §8.0 говорит «读/写时序(8080 时序) 参考 IC SPEC», то есть отсылает к
  даташиту самого ILI9488, **которого у нас нет**;
- поставщик пишет, что для 3.5″ последовательный интерфейс не рекомендуется
  (§2.5) — то есть запасной режим заведомо медленный.

**Это главный неразобранный риск блока.** На схему он не влияет: разводка под
оба интерфейса как раз и есть страховка. Но обещать, что 8080 поедет с первой
попытки, оснований нет.

### 7.10 Даташита ILI9488 у нас нет

Всё, что известно о контроллере, взято из спеки модуля и листа применения.
Даташита самой микросхемы в `docs/` нет, и на два вопроса ответить нечем:
тайминги шины (§7.9) и что именно панель делает с `DB` в SPI-режиме (§7.5).
Стоит скачать — это единственный пробел в источниках блока.
